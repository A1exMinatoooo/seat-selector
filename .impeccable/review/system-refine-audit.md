## layout：结构问题与答案

1. **阅读顺序**：页面标题→说明→分组→字段→操作总体明确。新建/编辑活动中的动态票务与座位配置是高密度区，建议清晰 legend 和组间留白，不再叠加卡片。
2. **分组与节奏**：导入和手工录入、地点新建和列表、活动配置和状态操作应保持分区；靠近字段的说明/错误比单独浮动 toast 更可追踪。
3. **结构与密度**：已确认 320px 的活动新建、草稿编辑、影院/影厅座位编辑器缩放工具栏 `nowrap` 会裁掉“缩小”按钮。新建页按钮边界 **-29.03…18.97px**，工具栏 **67…253px**。位置证据为 `src/app/globals.css` 的 `.seat-grid-viewport-toolbar`，不是 `.layout-controls` 三列规则。建议工具栏可换行/按容器宽度排列，保留可触达按钮；尚未写入生产或此版方案截图。
4. **适配**：所有已测管理页面的 document 宽度正确；参与者表格中的右侧动作位于内部横向滚动区，不能把它们的初始屏外坐标当成页面横溢。建议加强滚动提示/键盘焦点可见性。
5. **极端数据**：320px 长中文选项完整显示；下拉 listbox 为 **52…268px**，日历 **7…315px**，时间弹层 **25…295px**，均在视口内。长活动名、候选身份和连签场次仍需按真实上限逐项验证；顶部连签通知当前以省略号保留短行，为源码风险，不是已复现丢失倒计时。
6. **对齐与操作**：保存、下载、危险动作分层；保持已有列降级和48px字段高度。不要为了整图显示而认定缩放后的座椅触控已达44px。
7. **键盘/读屏顺序**：DOM顺序总体与表单阅读顺序一致；共享 NumericInput 的错误关联实测有效。React Aria 的隐藏 native input/select 是提交辅助节点，不能把它们 -1px 坐标或无独立名称误报为可见字段缺陷。

机械 layout 扫描为 `[]`，但没有识别上述真实工具栏裁切；扫描不是视觉质量证明。

## typeset：中文与全站字体

### 字体来源/实际命中

- `src/app/layout.tsx` 导入全局CSS、`lang="zh-CN"`；全站只有全局CSS和首页CSS Module，没有 `next/font`、`@font-face`、远程字体或下载字体。
- `src/app/globals.css:26–27` 为 `Arial, "PingFang SC", "Microsoft YaHei", sans-serif`；按钮/输入继承。Arial是拉丁/数字的声明首选，**不能说实际中文由Arial绘制**。
- 本机 Chromium 的活动新建标题经 `CSS.getPlatformFontsForNode` 实测：**PingFang SC / PingFangSC-Semibold**，6个中文 glyph，非自定义字体。没有实测Windows、Android或Linux的字体命中。
- 低风险候选栈：保留 `Arial, "PingFang SC", "Microsoft YaHei"`，其后加入 `"Noto Sans CJK SC", "Noto Sans SC", sans-serif`。仅使用系统已安装字体，不下载大中文字体；候选名称不保证各设备实际安装。若改为 `system-ui` 优先，拉丁/数字风格会变化，需另外比较，不默认替换。

### 角色与层级

| 角色 | 当前 | 建议方向 |
|---|---|---|
| 全局/首页展示标题 | `.98`行高、`-.055em`字距；流动字号最大92/72 | 中文标题接近0字距、约1.15–1.25行高；英文展示字距单独保留 |
| 管理标题 | 窄屏新建页实测38px字级、37.24px行高、-2.09px字距 | 降低夸张展示比例，固定任务层级；核验长中文标题换行 |
| eyebrow | 12px、800、`.22em`；首页`.2em/.18em` | 英文短眉题可保留高tracking；中文/混排接近0–.02em |
| 正文/表单 | 常规14–16；共享字段16px/24px | 保留字段16/24；正文/说明形成少量明确角色 |
| 标签/状态/元数据 | 12–14，700/800分散 | 统一角色，不把所有小字加到800 |
| 座位号/奖品/票据 | 48/32、24、12等；数字部分tabular-nums | 保留票据与数字对齐；中文座位/奖品完整换行 |

- **P1**：全局 `h1`（globals.css:30）与首页 heading（page.module.css:70–71）的 `.98/-.055em` 不适合多行中文。现有预览虽已放宽部分标题，中文专用字距仍值得进一步统一；本轮不偷偷改生产字体。
- **P2**：800的实际 face/合成取决于平台；本机标题命中Semibold，不据此断言Windows/Android也如此。不为追求“统一800”加载大字库。
- 正文行宽随页面任务决定，表单不能套长文章measure；长文本以完整换行和稳定控件高度为先。数字tabular-nums沿用。
- 系统字体没有额外加载布局偏移；焦点与错误关联已有共享模式。720px等效重排检查不替代200%真缩放或移动系统文字放大。
- type机械扫描的Arial“常见字体”提示在本项目视为**保留既有身份的有意选择**；字号超出DESIGN ramp为既有规范/实现不一致的advisory，不擅自修复DESIGN漂移，也不为消除提示而替换品牌字族。
